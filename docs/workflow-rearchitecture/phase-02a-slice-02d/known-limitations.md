# Known Limitations — Slice 2D

1. **`readonly@demo-ac-services.local` remains unremediated** — genuinely blocked pending a product decision (accept `staff` mapping's capability increase, invest in closing the read-only coverage gap first, or deactivate). Migration 144 cannot apply until this is resolved.
2. **`StaffPermission` override wiring gap is documented, not closed** — closing it (either a per-request DB lookup or JWT-embedding at login) is a real, scoped, but non-trivial change to the authentication/authorization core, left for a dedicated future slice.
3. **Read-only mutation-guard coverage gap (2 of ~16 routers) is documented, not closed** — extending `require_tenant_mutation_permission` to the other ~14 tenant routers requires individual per-file review (not every `POST` is a mutation deserving this guard) and was judged too large for this slice's bounded scope.
4. **Session revocation's Redis-key dependency is documented, not fully implemented** — the remediation script updates `user_sessions.revoked_at` but does not yet write the corresponding `serviceos:session:revoked:{session_id}` Redis key that `get_current_user`'s actual runtime check reads. No practical impact for this slice's one applied remediation (0 sessions existed), but must be added before remediating an account with live sessions.
5. **Seed script's live idempotency was not end-to-end re-verified** — its own `ALLOW_DATABASE_RESET` safety gate was deliberately not overridden, so the fix was verified via static review and isolated unit tests (mocked DB) rather than a full live re-run.
6. **Workstream 4's 16-action test matrix is only partially covered** — direct permission-check tests exist for a representative subset, not a full HTTP-level test per action per persona (see `test-report.md` for the specific reasoning).
7. **Whether service-layer authorization matches router authorization was not comprehensively re-verified** beyond the 2 specific paths already audited in Slice 2C.
8. **Intelligence KB field's user-facing UI label was not updated** — only the backend model docstring and a regression test were added; the frontend "Allowed Roles" label remains potentially misleading to an admin who doesn't read backend code.
9. **Pre-existing duplicate-operation-ID warnings** in `service_setup/templates_router.py` remain, unrelated, not fixed (same as every prior slice).
