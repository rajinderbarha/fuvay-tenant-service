# Documentation Corrections (Qualifying Slice 2F-16 Claims)

| 2F-16 claim | Correction |
|---|---|
| `invoice_payment.create_invoice` tenant and approved-status validation "closes" the invoice-lineage gap | Qualified — 2F-16 validated only `quote.tenant_id`; it never validated `quote.job_id`/`quote.customer_id` against the invoiced ServiceJob, leaving a same-tenant cross-ServiceJob/cross-customer substitution possible. Closed this slice — see `quote-servicejob-customer-lineage.md`. |
| Full domain-integrity closure (implied by 2F-16's fixes) | Corrected — domain-integrity closure required PROVING the invoice references the exact approved quote for the exact ServiceJob with matching customer identity, which 2F-16 did not verify. Now proven, see `direct-invoice-integrity-test-matrix.csv`. |
| Full privacy closure (implied by 2F-16's `get_quote` filtering fix) | Corrected on two fronts: (1) `QUOTE_NOT_FOUND`/`QUOTE_ACCESS_DENIED` remained externally distinguishable for reads — closed this slice (`privacy-error-equivalence.md`); (2) not all customer reads were field-audited — `list_quote_events` leaked provider-only draft-editing events, and `customer_approve`/`reject`/`request_revision`'s RESPONSE bodies still exposed `provider_internal_notes` (2F-16's fix only covered `get_quote`'s own read path) — both closed this slice. |
| Final-state immutability (2F-16's `ITEM_EDITABLE_QUOTE_STATUSES` lock) | Qualified — 2F-16 only verified ITEM mutations were locked; this slice additionally verified the full customer-visible field/state matrix (`final-state-immutability-matrix.csv`) including totals, currency, association fields, and decision fields, confirming no additional gap exists beyond the item-lock 2F-16 already closed. |
| Invoice safety claimed sufficient with only tenant and approved-status checks | Corrected — see the first row above; ServiceJob and customer identity matching were also required and are now enforced. |
| Canonical role closure of `require_owner_or_office_staff_mutation` (implicitly assumed correct by 2F-16's choice to use it) | Confirmed, not corrected — this slice PROVED (via `TestCanonicalDependencyRoles`, 6 executed tests) that the dependency admits canonical roles only and denies `office_staff`/`tenant_manager`/`manager`/`supervisor` as literal role values, closing the previously-unproven assumption. |
| "Hidden items cannot affect customer payable amount" (implicit in 2F-16's `_copy_from_quote` filtering) | Corrected — `_copy_from_quote`'s filtering was always correct for the eventual INVOICE, but the DISPLAYED quote total shown to the customer via `get_quote` did NOT reconcile to the visible items shown alongside it (included hidden-item cost). Closed this slice with a total/invoice reconciliation test (`hidden-item-total-test-matrix.csv`). |

No code-level authorization decision from 2F-16 is reversed — every correction above is either a service-layer lineage/validation hardening or a read/response-filtering completion, not a change to who can perform any action.
