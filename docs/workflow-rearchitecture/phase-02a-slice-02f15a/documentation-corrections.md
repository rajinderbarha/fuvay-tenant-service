# Documentation Corrections (Superseding Slice 2F-15 Claims)

Slice 2F-15's own documentation (`docs/workflow-rearchitecture/phase-02a-slice-02f15/`) made several claims that this slice's mission required be corrected or superseded. This file records the corrections; the original 2F-15 files are left in place for history, with a superseded notice added to `approval-gate.md` (see below) rather than being rewritten.

| 2F-15 claim | Correction |
|---|---|
| "SECURITY_CLOSED for the entire Booking router" | False — 6 routes (`cancel_booking`, `accept_reschedule`, `reject_reschedule`, `request_reschedule`, `add_note`, plus `booking_preflight` uncounted) remained unverified. Corrected: full-router closure is now achieved as of **Slice 2F-15A** (10/10, runtime-verified exit 0). |
| "CUSTOMER_AUTHORITY_PROVENANCE_CLOSED" | Overstated — a provider-created, confirmed Booking could still establish relationship authority by itself (self-bootstrap risk), and no independent-evidence requirement existed for `convert_to_job` or direct `create_job(booking_id=...)`. Corrected: provenance is closed as of **Slice 2F-15A** via the `changed_by_role`-based predicate and independent-relationship-proof requirement. |
| "GLOBAL_COVERAGE_CLOSED before persona reclassification" | The provisional 174/221 figure counted `booking_preflight` as a real mutation row and left 5 booking routes unprotected inside that denominator without reclassifying personas. Corrected: canonical coverage is now **179/220**, see `canonical-coverage-reconciliation.md`. |
| "the claim that legacy data audit is merely future product work" | Partially corrected — the SPECIFIC provenance risk (provider-created Bookings self-bootstrapping) is now a closed SECURITY item, not merely a product question. What remains genuine product-policy work is narrower: see `product-decisions-required.md` (truly unrecorded legacy rows; first-ever assisted booking for a brand-new phone-order customer). |
| "the claim that six unverified routes do not block module closure" | Corrected — those 6 routes DID block full-router runtime verification (`unverified_count: 6`, exit 1), and this slice's mission explicitly required treating that as blocking. Full closure required fixing all 6 (5 fixed as mutations, 1 reclassified as a false positive). |
| "the claim that every qualifying Booking is trusted by induction" | Corrected — this "induction" argument (2F-15's own reasoning, itself inherited from 2F-14G) assumed every future assisted Booking would go through 2F-15's own validation, but did not account for (a) Bookings predating that validation, or (b) a chain of provider-created bookings each superficially "confirmed." Corrected: trust now requires demonstrated customer origination, not merely qualifying status. |
