# Known Limitations — Slice 2C

1. **Both invalid accounts remain unremediated** — by design, pending human/product decisions documented in `remediation-decision-register.md`.
2. **The DB CHECK constraint (migration 144) cannot be applied** until those accounts are resolved — this is intentional, not a defect, but it does mean the integrity guard is not yet actively protecting the database.
3. **Session revocation logic was designed but not built** into the remediation script this slice, since no apply occurred to exercise it. A future slice applying remediation must add this before running `--apply --confirm` for real, per `token-session-impact.md`'s finding that JWTs embed role at issue-time and won't reflect a role change until the session is revoked or the token naturally expires/refreshes.
4. **Notification-on-remediation was not automated** — deliberately left as a manual decision (see `token-session-impact.md`).
5. **Intelligence KB's `allowed_roles_json` remains DISPLAY_ONLY** — conclusively investigated, disposition documented, but the underlying question (build real enforcement, or remove the non-functional UI) is a product decision not made this slice.
6. **The audit-write code path in the remediation script was never executed live** — verified correct by code review and by analogy to the structurally identical, already-proven `change_platform_role` audit call, but not exercised end-to-end this slice.
7. **Whether other, previously-unknown role-write paths exist beyond what was searched** cannot be ruled out with absolute certainty — the audit covered every path discoverable via the search strategies used (grep for `role=`/`.role =` patterns, direct reading of every hit), but a sufficiently obscure or dynamically-constructed write path could theoretically exist unfound.
8. **`get_current_user`'s JWT-embedded role finding is new this slice** and has implications beyond just these 2 accounts (any future role change for any user has the same "stale token" characteristic) — this is now documented but represents a small, pre-existing architectural characteristic, not something this slice was asked to fix.
9. **Pre-existing duplicate-operation-ID warnings** in `service_setup/templates_router.py` remain, unrelated, not fixed (same as every prior slice).
