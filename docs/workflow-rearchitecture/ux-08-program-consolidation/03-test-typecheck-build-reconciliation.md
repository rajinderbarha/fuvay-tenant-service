## Tenant Portal (`frontend/tenant-portal`, same workspace install as above)

- `npx vitest run` → **Test Files: 3 failed | 13 passed (16) / Tests: 11
  failed | 42 passed (53)**.
- **Real, genuine, pre-existing defect found (not fabricated, not a UX-08
  regression):** the 11 failures are all `TypeError: Cannot read properties
  of null (reading 'useState')` inside `SetupWizard.tsx` and
  `PartsRequestList.tsx` — the classic duplicate-React-instance failure mode
  (a component rendering against a different React module instance than the
  one the test renderer/hook runtime is using). Root-caused by inspecting
  installed versions directly:
  ```
  frontend/tenant-portal/node_modules/react/package.json  -> 19.2.7
  frontend/super-admin/node_modules/react/package.json    -> (not nested; hoisted)
  node_modules/react/package.json (workspace root, hoisted) -> 19.2.0
  ```
  and the package.json source pins themselves:
  ```
  frontend/tenant-portal/package.json: "react": "19.2.7", "react-dom": "19.2.7"
  frontend/super-admin/package.json:   "react": "19.2.0", "react-dom": "19.2.0"
  ```
  `frontend/tenant-portal`'s `package.json` pins a **different** React patch
  version (19.2.7) than the rest of the workspace (19.2.0), which npm
  workspace hoisting cannot resolve into a single shared copy — so
  `tenant-portal` gets its own nested `react`/`react-dom`/`react-test-render
  er`-adjacent tree, and whichever copy the Vitest/jsdom/testing-library
  harness picks up at runtime for hooks doesn't always match the one the
  component module resolved for its own `import React`. This is the same
  *class* of bug documented in this repo's own commit history for the
  staff-app (commit `514169b`, "duplicate-react-test-renderer-instance
  bug") — a recurring dependency-pinning hazard in this repo, now also
  reproduced independently in `frontend/tenant-portal`.
- **Disposition: documented as a real, pre-existing environment/dependency
  defect, NOT fixed this pass.** Fixing it correctly would mean either
  re-pinning `frontend/tenant-portal`'s React version to match the rest of
  the workspace (19.2.0) or vice-versa, verifying no other breakage results,
  and re-running the full tenant-portal + super-admin + shared
  `design-system` package suites end-to-end — this is a real dependency-
  version-alignment task, not the "small, evidence-backed frontend
  correctness fix" UX-08's brief permits (that bar is meant for things like
  removing a dead fixture route, not re-pinning a shared dependency across
  three workspace members). Filed as a backend/tooling-independent
  **frontend ticket** in Workstream 12-13 (doc 07,
  `TICKET-UX08-001-tenant-portal-react-version-mismatch`).
- The 13 passing test files / 42 passing tests are unaffected and represent
  real, currently-green tenant-portal coverage.
