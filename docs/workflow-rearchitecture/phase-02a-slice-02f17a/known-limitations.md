# Known Limitations

- No live database/server verification was performed, consistent with every prior slice.
- **The customer-mutation route count in `global-coverage-reconciliation.md` (6) is a PARTIAL figure**, covering only the customer routes tracked within modules this initiative has explicitly touched (Booking's 3, quote_checklist's 3). A full application-wide customer-mutation census (24 `CUSTOMER_ROLE_ONLY_NOT_TENANT_SCOPED` routes exist per the runtime tool's own guard_status tally, plus an unknown number of additional customer-prefixed routes never individually classified by this initiative) was NOT performed this slice — no dedicated, consolidated "customer canonical CSV" exists in this codebase, mirroring the tenant CSV's structure. This is an honest scope gap, not a claim of completeness.
- **The missing-tenant-mutation heuristic (`provider/`, `staff/`, `tenant/` path-segment prefix) was initially implemented requiring a literal `/v1/` lead-in, which undercounted candidates** — some routes report their path without the `/v1` segment reflected in route introspection (the prefix is applied at `app.include_router(prefix="/v1")` time and not always visible on the route object itself). Corrected mid-slice to normalize both forms before matching; re-run confirmed the SAME result (0 genuinely missing tenant mutations) under the corrected, more robust methodology — the initial undercount risk did not change the conclusion, but is disclosed here for transparency about the investigation process.
- **A full manual review of all ~1186 routes' individual business-capability was not performed** — the missing-mutation discovery relies on the path-prefix heuristic (now corrected, see above) plus the codebase's existing `guard_status`/exemption-list machinery, not an independent line-by-line audit of every route's source code. This is consistent with the depth of analysis performed for every prior slice's coverage reconciliation in this initiative.
- The pre-existing `test_phase2d_tenant_access_model.py` test failure (stale hardcoded file-count assertion) was NOT fixed this slice — fixing an unrelated test's stale assertion was judged out of this slice's scope (a discovery/reconciliation slice, not a general test-maintenance slice), though it is honestly reported in `regression-report.md`.
