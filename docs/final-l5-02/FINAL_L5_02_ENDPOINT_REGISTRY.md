## Real finding: 7 duplicate operation IDs = a duplicate router mount
All 7 duplicates are the **service-setup templates** router mounted at **two prefixes simultaneously**:

| Operation | Path A (Sprint 34F) | Path B (P0 Enterprise) |
|---|---|---|
| list_templates | `/v1/admin/service-setup-templates` | `/v1/admin/service-setup/templates` |
| create_template | `/v1/admin/service-setup-templates` | `/v1/admin/service-setup/templates` |
| get/update/delete/archive/publish | `/v1/admin/service-setup-templates/{id}...` | `/v1/admin/service-setup/templates/{id}...` |

Root cause: **two parallel service-setup-template implementations** are both mounted —
- `app.engines.admin_catalog.service_setup_template_router` (Sprint 34F, migration 058 schema)
- `app.engines.service_setup.templates_router` (P0 Enterprise, migration 097 schema — the canonical winner, matches the live DB)

This is the router-level manifestation of the same duplication that produced the 058/097 migration conflict fixed in FINAL-L5-01B-PLUS. Classification: **DUPLICATE**. The Sprint 34F router (`admin_catalog.service_setup_template_router`) operates against the 058 schema, which no longer exists in the DB (097's schema won) — so it is likely **BROKEN at runtime** for any query referencing 058-only columns (`slug`, `metadata_json`). Carried to the bug register and deprecated-API register; **not removed this sprint** (needs a consumer audit + confirmation which frontend, if any, calls the Sprint 34F prefix).
