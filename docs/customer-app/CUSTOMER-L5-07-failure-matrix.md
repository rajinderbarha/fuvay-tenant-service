# CUSTOMER-L5-07 — Failure Matrix

| Failure | Detection point | Customer impact | Screen state | Message | Retry | Reconciliation | Analytics | Log level | Severity |
|---|---|---|---|---|---|---|---|---|---|
| Address list fails to load | `useAddresses` `isError` | Cannot select/manage addresses | Full-page error | `address.loadError` | Yes | N/A | Implicit `api.error` | warn | P1 |
| Address create/update fails (validation) | `createAddress`/`updateAddress` mutation error | Form stays open with entered values preserved | Toast: `addressForm.saveFailed` | Same | Manual (re-tap save) | No draft mutation attempted yet | Implicit | warn | P2 |
| Address ownership mismatch | Backend 404 on get/update/delete | Operation fails safely, no data ever shown | Generic error state | Generic error text | Where applicable | No foreign data ever rendered | Implicit | warn | P1 |
| Location permission denied | `requestForegroundPermissionsAsync` returns `granted: false` | "Use current location" has no effect beyond a notice | Inline notice: `addressForm.permissionDenied` | Same | Manual entry remains fully available | N/A | `media_picker_permission_denied`-style, `current_location_requested` with `result: "permission_denied"` | info | P3 |
| Location/reverse-geocode unavailable | `getCurrentPositionAsync`/`reverseGeocodeAsync` throws or returns no result | Same — notice shown, manual entry available | Inline notice: `addressForm.locationUnavailable` | Same | Manual entry / retry the button | N/A | `current_location_requested` with `result: "unavailable"` | info | P3 |
| Attaching address to draft fails | `updateDraft` mutation error (from `AddressListScreen.handleSelect`) | Customer stays on the address list; selection has no visible effect | No dedicated error UI this pass (see known-gaps) | N/A | Implicit — customer can tap the address again | Draft's `address_id` unchanged | `draft_save_conflict` | warn | P2 |
| Serviceability check fails (network/timeout) | `checkServiceability` mutation error | Cannot see availability result | Full-page error | `serviceability.loadError` | Yes (re-runs the mutation) | Draft's `serviceability_status` unchanged | `serviceability_check_failed` | warn | P1 |
| Not serviceable | Real `serviceable: false` result | Honest unavailable state, real backend message shown verbatim | Unavailable state with "Change address" action | Real `message`/`reason_code`-derived copy | N/A (not a failure, a real result) | Draft's `serviceability_status = "not_serviceable"` | `serviceability_check_completed` (serviceable: false) | info | NOT_APPLICABLE (correct, honest behavior) |
| `preferred_time_window` save fails | `updateDraft` mutation error inside `ServiceabilityScreen`'s continue handler | Customer still proceeds to the next boundary — the free-text note is best-effort, not a hard gate | No dedicated error UI (see known-gaps) | N/A | N/A | Draft's `preferred_time_window` unchanged | Implicit | warn | P3 |
| Offline | Existing `ApiError` `network_error` category on any of the above | Same generic failure UI per-operation | Various (see above) | Generic error text | Yes, once reconnected | Unaffected | N/A | N/A | P3 |
| Logout/account switch mid-flow | `queryClient.clear()` (CUSTOMER-L5-02 pattern, reused) | Redirected away, no foreign state persists | Redirected to Authentication/BaselineLanding | Existing auth flow copy | N/A | Address cache discarded | N/A | N/A | NOT_APPLICABLE (correct behavior) |
| Wrong customer address ID (theoretical, unreachable via real UI) | Backend 404 | N/A — no real UI path constructs this | N/A | N/A | N/A | N/A | N/A | N/A | NOT_APPLICABLE |
