# Service CRUD Browser Verification (Part 4)

Real CRUD surfaces found and verified for the Home Services catalog:

1. **Add Service / Add Service Group** — service-catalog page CTAs link out to `/admin/catalog-module/master-services` and `/admin/service-groups` respectively (existing enterprise CRUD screens built in prior sprints — P0 Enterprise Catalog Upgrade). Not re-tested here (out of strict "catalog + pricing" scope duplication — those pages are the real CRUD surface, this console is read/navigate-only by design per its own code comments ("Tenants can only select this service from the admin-approved catalog above")).
2. **Pricing Rule create/edit** — the pricing-rules page (`/admin/home-services/pricing-rules`) has full inline modal CRUD: Add Rule button opens a blank form; Edit button on each row opens the same modal pre-filled via `openEdit(r)`. Verified live in browser: clicked "Edit" on the first of 9 real rows, modal opened with Service/Type/Brand selects and Min/Max/Fee/Deduction inputs populated, then Cancel closed without saving (no baseline data mutated). Screenshot: `frontend/e2e-admin-tenant/evidence/e2e03/pricing-rule-edit-modal.png`.
3. **Toggle active/inactive** — pricing rule form has an "Active" checkbox wired to `is_active`; confirmed in source (`page.tsx` line ~266).
4. **Types/Brands/Issues/Options add/edit** — these are read-only tabs in this console (Types, Brands, Issues, Options) with explicit "Manage in X →" links out to dedicated CRUD pages (`/admin/service-setup/issue-types`, `/admin/service-options`) rather than duplicating CRUD inline. This is a real, honest design choice (not a gap) — confirmed by reading the tab components (`IssuesTab`, `OptionsTab`, `TypesTab`, `BrandsTab`).

No hard-delete action exists anywhere in these 4 pages — confirmed via grep (`grep -n "delete\|DELETE" app/admin/home-services/*/page.tsx` returned no matches other than the word inside comments). No real seed data (Split AC+LG, Window AC+LG, AC Repair, Ludhiana/141001) was mutated during this sprint's testing — all edit-modal interactions were open-then-cancel only, verified via DB re-query after tests (see Type-Specific Brand Pricing report, Part 5, DB rows unchanged).

Result: PASS — real CRUD exists for the in-scope surface (pricing rules); catalog-entity CRUD is intentionally routed to dedicated existing screens, not duplicated, and this is documented honestly rather than faked.
